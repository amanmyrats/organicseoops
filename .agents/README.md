# Shared Agent Resources

This directory contains provider-neutral Markdown used by coding agents.

For every future creation or modification of agent instructions, agents, subagents, skills, or references, follow the project-root [Universal Agent Resource Maintenance workflow](../AGENTS.md#universal-agent-resource-maintenance) (D115). Maintain canonical shared files and thin native adapters, with direct-reading fallback and documented host-specific exceptions.

Primary-agent model and reasoning selection belongs to the coding tool's current session or personal defaults (D116). Do not add project-level primary model/reasoning pins unless explicitly requested. Specialist subagent assignments remain explicit in their adapters.

- `rules/` contains task-specific requirements. These files are loaded only when `AGENTS.md` or a skill directs an agent to read them.
- `skills/` contains Agent Skills-compatible workflows. Each skill uses a `SKILL.md` file with only portable frontmatter.
- `references/` contains concise maps to authoritative project material. References provide context; they do not override rules or canonical documents.
- `roles/` contains provider-neutral reviewer instructions. These are loaded explicitly by a host adapter or a parent agent, not automatically registered as subagents.

`AGENTS.md` is the shared root instruction file for OpenCode and Codex CLI. `CLAUDE.md` imports it for Claude Code. Do not duplicate shared instructions in provider-specific directories; add a thin adapter only when a tool cannot discover the neutral source directly.

## Implementation Continuity

The [implementation guide](../docs/IMPLEMENTATION_GUIDE.md) provides start/resume prompts and routes these shared resources by task. Use the [task ledger](../docs/IMPLEMENTATION_TASKS.md) for coding instructions and the [checkpoint](../docs/IMPLEMENTATION_STATE.md) for durable partial progress, verification and next steps. These files work across models/hosts without requiring subagent registration or prior chat history; application implementation still requires an explicit start request.
